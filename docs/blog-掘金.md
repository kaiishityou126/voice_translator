# 用 Tauri + Rust 撸一个「音频不出本机」的实时语音翻译桌面应用(开源)

> TL;DR:远程会议里客户一半说英文、一半说日文,同事听不懂;市面上能打的实时翻译几乎全是订阅制云端方案($60~150/月起,音频还要上传)。于是我用 **Tauri 2 + Rust + React** 写了个免费开源、**语音识别全程在本机**的替代品。仓库直达:**https://github.com/kaiishityou126/voice_translator**

## 背景:一个真实的痛点

做跨境业务的远程会议,客户操着英文、日文轮流上,语速还快。国内同事跟不上,只能会后啃录音。想找工具救急,结果:

| 产品 | 价格 | 方案 |
|---|---|---|
| Palabra.ai | $60/月起,Pro $150/月 | 云端 |
| KUDO.ai | 企业级,联系销售 | 云端 |
| Teams / Zoom 翻译字幕 | 需商业付费档 | 云端 |

两个槽点:**要么收费,要么音频得上云**。对涉密 / 商务谈判场景,音频上云是硬伤。

那就自己写一个:**免费、开源、音频不出本机**。项目名 **海星同传 · SeaStar**。

## 架构一览

```
系统音频环回 / 麦克风
   → 降噪 + 重采样(48k→16k)
   → VAD 分段(Silero)+ 攒句定稿
   → sherpa-onnx 进程内识别(SenseVoice / Qwen3-ASR)
   → 云端 / 本地 LLM 翻译
   → 双语字幕 + 可选悬浮窗 + 可选 TTS 回灌
```

技术选型:

- **Tauri 2 + Rust** 后端,**React 19 + TypeScript + Vite** 前端;
- 识别走 **sherpa-onnx 静态链接进程内推理**——不起 sidecar、不开 HTTP 端口,onnxruntime 只链一份;
- **纯 CPU 推理**,无需独显;
- 双向并发流水线:入站(听对方 → 字幕)与出站(你说话 → 译音回灌)两条方向相反的流水线用有界 mpsc 串联,溢出丢弃保实时,绝不无界堆积。

## 功能清单

- 🎧 **翻译任何系统声音**:抓系统环回,不绑定 Zoom/Teams/腾讯会议,视频直播播客通吃;也能翻麦克风;
- 🔒 **隐私优先**:识别在本机,只有文本可选走云;配本地 **Ollama** 可做到**零数据外发**;
- 🗣️ **双向语音回灌**:配 VB-CABLE 虚拟声卡,把你的话译成对方语言用 TTS「讲」进会议;
- 📝 **实时双语字幕** + 置顶悬浮窗(独立 Vite 入口);
- 🌐 **多翻译引擎**:OpenAI 兼容 / 本地 Ollama / Google 免费 / 纯字幕;
- 🧠 **会话重点提炼**(LLM 总结)+ **历史回看**;
- 🎯 **说话人声纹门控**:回灌时只放行本人声音,挡掉旁人。

识别引擎二选一:**SenseVoice**(int8,快,中英日韩粤)/ **Qwen3-ASR**(LLM 解码,准,约 30 语言 + 中文方言)。模型首次使用按需下载,不打包进安装包。

## 一些工程上的坑(值得单独展开)

- **实时断句**:VAD 分段只是「喂料」,靠停顿阈值 + 单句上限「攒句」成完整句再翻译,兼顾完整度与延迟;
- **防音频回环**:开回灌时 TTS 只灌 CABLE Input、绝不进默认输出,否则环回会把自己的 TTS 又转一遍;
- **有界通道 + 代际守卫**:通道满 `try_send` 丢弃,流水线代号自增丢弃旧代迟到事件,避免「停止要点两次」的竞态。

(这几块后面可以单独写深入篇。)

## 老实说说局限

- **实时性看引擎**:SenseVoice 接近实时;Qwen3 更准但 CPU 下偏慢,适合非实时场景;
- **多人说话人区分**还不够稳;
- **同音词 / 专有名词**偶尔翻车(识别层);
- **目前只在 Windows 验证**,macOS(ScreenCaptureKit / cpal)代码写好了但没真机跑通。

现阶段最稳:**SenseVoice + 单向字幕听对方**。
