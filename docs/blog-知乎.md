# 客户一半说英文一半说日文,同事听不懂——于是我用 Rust 撸了个「音频不出本机」的实时翻译软件

## 起因:一场听不懂的远程会议

做外贸 / 跨境的朋友大概都懂这个场景:

一场远程视频会议,客户里有说英文的、有说日文的,噼里啪啦讲得飞快。我们这边的小伙伴,英文勉强跟,日文基本抓瞎——只能会后靠录音慢慢啃,或者临时抓个人翻译,效率极低,还常常错过关键信息。

我第一反应是找现成工具。结果一圈调研下来,心凉了半截:**能打的基本都收费,而且是订阅制**。

- **Palabra.ai**:$60/月起,Pro 档 $150/月;
- **KUDO.ai**:企业级,直接「联系销售」;
- Teams / Zoom 自带的翻译字幕,像样的也要商业付费档。

而且更让我在意的是另一点:**这些方案几乎都是云端的——你的会议音频要上传到别人服务器**。对一些商务谈判、涉密沟通来说,这是个绕不过去的坎。

于是我决定自己写一个。目标很明确:**免费、开源、音频不出本机**。

它叫 **海星同传 · SeaStar**。

## 它能干什么

一句话:**把你电脑上正在播放的任何声音,变成实时双语字幕;甚至能把你说的话,翻译成对方的语言「讲」进会议里。**

### 🎧 翻译任何系统声音,不绑定软件

不是某个会议软件的插件。它抓的是**系统音频环回**——不管声音来自 Zoom、Teams、腾讯会议,还是浏览器里的视频、直播、播客,只要你电脑在放,它就能翻。也可以切到麦克风翻你自己说的话。

### 🔒 隐私优先(这是它最核心的取舍)

**语音识别在本机完成**,只有识别出来的**文本**才发给翻译服务。如果你把翻译引擎设成本地的 **Ollama 大模型**,那就是**全程零数据外发**——音频、文本都不出这台电脑。这是所有云端竞品做不到的。

### 🗣️ 双向语音回灌(把翻译「说」进会议)

配合一个免费虚拟声卡(VB-CABLE):**你说中文 → 应用自动译成英文/日文,用语音替你讲进会议**,对方直接听到他们的语言;对方说话,你这边看双语字幕。相当于随身带了个同传。

### 📝 实时双语字幕 + 置顶悬浮窗

原文即时显示,译文紧跟其后。还有一个可拖动、永远置顶的悬浮字幕窗,看视频/开会时特别顺手。

### 🌐 多种翻译引擎,含免 key 选项

- **OpenAI 兼容**(GPT / DeepSeek / 通义 / 智谱 / Kimi):最准;
- **本地 Ollama**:离线、零外发;
- **Google 免费**:免 key 随手用;
- **纯字幕**:不翻译,只转写。

> 省钱又要实时的话,推荐把 OpenAI 兼容接口指向**智谱 GLM-4-Flash**(免费),说完一秒内就出译文。

### 🧠 还有一些顺手的小功能

- **会话重点一键提炼**(LLM 总结整场会议);
- **历史记录回看**;
- **说话人声纹门控**:回灌时只放行「你自己的声音」,挡掉旁边同事的杂音。

## 技术栈

- **Tauri 2 + Rust**(后端)+ **React 19 + TypeScript**(前端);
- 识别用 **sherpa-onnx 进程内静态链接**,不起 sidecar、不走 HTTP;
- 识别引擎二选一:**SenseVoice**(快,中英日韩粤)/ **Qwen3-ASR**(准,约 30 种语言 + 多种中文方言);
- TTS 用 **Kokoro** 多语合成;
- **纯 CPU 推理,无需独显**,Windows 开箱即用。

模型都是**首次使用按需下载**,不打包进安装包,保持体积干净。

## 老实说说局限(别被我上面吹的忽悠了)

开源项目,我更愿意把短板摆在明面上:

- **实时性看引擎**:SenseVoice 接近实时;Qwen3 更准但 CPU 下偏慢,适合非实时 / 高准确率场景;
- **多人会议的说话人区分**还不够稳,人多混说时归属会乱;
- **专有名词 / 同音词**偶尔翻车(这是识别层的锅);
- **目前只在 Windows 上验证过**,macOS 的代码写好了但还没真机跑通。

所以现阶段最稳的用法是:**SenseVoice +「听懂对方」的单向字幕**。双向语音同传更偏尝鲜。
